# Second Home

Three personal discoveries in an unfamiliar city, connected to the things you already love.

Live demo: https://second-home-taste-discoveries.daintytapir512.chatgpt.site

Public source: https://github.com/fernandoshanegihan-coder/SecondHome

## Run locally

Use Node.js 24 or newer and npm. Install dependencies with `npm install`, copy `.env.example` to `.env.local`, and enter your Qloo key there. Never commit that local file. Set QLOO_API_URL to the host supplied with your key (the hackathon default is https://hackathon.api.qloo.com).

Run `npm run dev` and open http://localhost:5173. Search for a city and explicitly choose the correct location, then search and select three to five different favourite artists, films, books, brands, or places. Optional budget and atmosphere preferences affect ranking only when Qloo provides supporting metadata.

## How it works

The server resolves names to Qloo IDs, searches Qloo Insights for places within the selected locality, compares available metadata with preferences, and returns up to three distinct discoveries. Explanations name only taste contributions returned by Qloo. Without contribution metadata, the app explains that the combined taste profile informed the selection.

Feedback retrieves fresh candidates, excludes existing and previously rejected places, and compares the alternatives. The workflow is bounded and deterministic; it does not use an LLM or need a model-provider key. No place facts are generated by a language model.

## Verification

- `npm test`: core resolution, query contracts, recommendation logic, validation, and route boundaries.
- `npm run typecheck`: TypeScript validation.
- `npm run build`: production build.
- `npm run test:e2e`: Playwright browser checks (requires Microsoft Edge or change the configured browser channel).
- `node --env-file=.env.local scripts/check-discovery.mjs`: live Qloo discovery and replacement. Uses API quota and outputs only public place metadata.

Tests use explicit network fixtures and never masquerade as a live integration. See docs/feasibility.md for live verification evidence and limitations.

## Privacy and limitations

No account or persistent profile is required. Preferences stay in page memory and are sent to the server and Qloo for the current request. Reloading clears browser state. The hosting provider and Qloo may retain operational logs according to their policies. The frontend does not receive your Qloo key.

City coverage varies. Fewer than three supported results are displayed honestly. Prices and opening hours are not live; check them before visiting. Closer refers to the selected city centre rather than a home address. Quiet and budget comparisons depend on available metadata and are not guarantees. No bookings, social matching, safety assessments, or route planning.

## Hosting

The project retains the Sites Vinext build integration and Worker entrypoint. Configure QLOO_API_KEY as a hosted runtime secret and QLOO_API_URL as a runtime variable. .openai/hosting.json contains only the Site identity and nonsecret configuration. A private preview is not a public hackathon demo; verify anonymous access before submitting. Public release also requires hosting-level quota and abuse controls.
